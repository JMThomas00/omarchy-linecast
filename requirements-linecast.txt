# Pinned, hash-verified install for the `linecast` backend this plugin was
# last reviewed against (see README.md -> Security -> Backend binding).
# Hashes are the sdist and wheel published to PyPI for this exact release:
# https://pypi.org/pypi/linecast/2.3.1/json
#
#   pip install --user --no-compile --require-hashes -r requirements-linecast.txt
#
# `--require-hashes` fails closed if PyPI ever serves different bytes for
# this version, or if a transitive dependency shows up unpinned.
#
# `--no-compile` matters here, not just as an optimization: pip
# byte-compiles by default and writes those .pyc files' paths into RECORD,
# which this plugin's own verifier (ptyrun.py's resolve_verified_linecast())
# treats as "a file outside the reviewed manifest" and refuses to run --
# the manifest is generated from the pristine wheel, which never contains
# install-time bytecode. See README.md -> Security -> Backend binding for
# how runtime-generated bytecode (written the first time linecast actually
# *runs*, independent of which installer put it there) is handled instead.
#
# Pinned to 2.3.1 rather than a later release: 2.4.0 changed every --live
# view's redraw strategy to absolute per-row cursor addressing with no
# plain newlines at all, which this plugin's renderer can't display yet
# (every tab shows "No data") -- see README.md -> Known limitations and
# github.com/JMThomas00/omarchy-linecast/issues/5.
